# 保险销售客户端经营归因：因子库深挖与扩充方案

研究日期：2026-09-17。适用当前“保险销售客户端经营归因 Agent”的 A 线实验归因、B 线异常探索和 C 线盯防。结论基于本地交付包核对和公开研究；没有接入企业生产数据，没有实测新增因子的效果。

## 1. 本次结论

因子库最值得补齐的是**保险产品与价格、销售全链路、续保与服务、客群结构和测量质量**。继续累加泛化的宏观指数，往往不如把一个“报价问题”拆成同保障价格差、报价变化、资格阻断和有效期更有调查价值。这是结合当前覆盖情况提出的优先级判断，尚不是效果排序。

本次交付 38 个新增候选定义：产品与价格6、体验与组件6、投保与核保6、续保与服务6、客群与渠道4、外部环境4、数据质量6。优先级为 P0 19项、P1 16项、P2 3项；P0代表优先补采集和口径，并不代表全部应同时加入回归。另提出8项现有因子的细化方案，不把细化、派生和交互重复算成新增父因子。

每条新增候选包含：稳定 ID、操作化公式、数据源需求、范围粒度、候选时间窗、角色、验证方法、主要陷阱与来源链接。所有记录均为 `research_candidate`，没有伪造观测值、授权信息或因果证据。

## 3. 深挖依据：哪些机制有研究支持

### 3.1 价格、支付负担与信任要拆开

Cole等人的印度降雨保险现场研究讨论价格、资金约束和信任对购买的作用。它支持将这些机制分别调查，但样本、险种和销售情境与国内线上保险明显不同。本次不迁移其弹性系数，也不把“顾问接通”直接等同“信任”。[原始研究（2013）](https://pmc.ncbi.nlm.nih.gov/articles/PMC3995033/)

据此提出同保障报价差、缴费方式和提交前后报价变化：三者分别对应相对价格、首期负担和预期落差。竞品更便宜，可能只是免赔额更高；月交首期更低，可能总成本更高。必须保留保障篮子、缴费期、费用与版本。

### 3.2 信息摩擦与选择质量比单纯点击更重要

保险信息摩擦研究提示，解释、推荐和选择结构可能改变消费者决策。本次据此把“困惑”从模糊情绪指数拆为解释版本、展示方案数和可验证理解结果；具体埋点和实验属于本项目设计，并非论文直接给出的标准。[Handel等，2015](https://www.nber.org/papers/w21759)

保险销售管理规则本身包含条款说明、产品信息展示及销售前中后管理要求。因此完整披露是边界条件，研究对象应是合法完整信息的呈现方式，而不是减少必要信息。该法规来源用于界定业务要求，不用作“披露一定提升转化”的效果证据。[《保险销售行为管理办法》](https://policy.mofcom.gov.cn/claw/clawContent.shtml?id=98055)

### 3.3 续保有自己的因子空间

Medicare Part D研究将注意力不足和切换成本作为续保惰性的不同来源。这个发现支持把新客购买和续保分开建模，新增到期日、提醒计划、续保价格变化和历史服务体验；不能直接照搬美国医疗保险的效应量。[Heiss等，2016](https://www.nber.org/papers/w22765)

同时，实验研究发现常见风险态度结构模型并不一定能很好预测保险选择。因此不建议先建一个未经验证的“用户风险偏好分”并把它当核心解释变量；先使用时间明确、口径可核对的行为和产品信息。[Jaspersen等，2019](https://www.nber.org/papers/w26508)

### 3.4 性能必须从综合延迟拆到可测机制

Google给出LCP、INP、CLS三个不同的浏览器体验指标，建议按访问分布P75和端类型评估；其良好阈值分别为2.5秒、200毫秒和0.1。这些阈值用于体验诊断，不能当作保险业务效果阈值，也不能直接应用到原生App。[Web Vitals](https://web.dev/articles/vitals)

W3C轮播模式对自动轮播暂停和焦点交互有明确建议。对应的新因子是轮播控制配置，而非仅记录一个泛化“轮播版本”。实验只能比较满足基本可访问性要求的方案。[W3C Carousel Pattern](https://www.w3.org/WAI/ARIA/apg/patterns/carousel/)

### 3.5 数据质量异常先于业务解释

Microsoft的SRM研究说明，分组人数失配可提示分流、触发和采集等问题，忽略它可能导致实验判断错误。本次据此将SRM、污染、重复、分母版本、可用延迟和支付承保对账列为独立质量诊断；后五项的具体定义是本项目建议，并非该文章逐项验证的保险指标。[Microsoft SRM](https://www.microsoft.com/en-us/research/articles/diagnosing-sample-ratio-mismatch-in-a-b-testing/)

### 3.6 外部环境应通过业务暴露关联

2024年监管文件涉及预定利率与市场利率挂钩及产品切换机制，适合引出“政策适用产品暴露”和“正式停售时间”因子。本文不将文件中的历史数值当作2026年现行利率上限；实际接入需按日期加载当时有效公告。[监管总局历史通知](https://www.nfra.gov.cn/cn/view/pages/ItemDetail.html?docId=1175200&itemId=928)

LPR公告可作为带发布日期的官方数据源示例，但LPR是贷款报价利率，不能替代储蓄产品比较所需的存款利率。宏观低频数据必须按首次公布和入仓时间对齐。[人民银行历史公告](https://www.pbc.gov.cn/zhengcehuobisi/125207/125213/125440/3876551/5625437/index.html)；[国家统计局月度入口](https://data.stats.gov.cn/easyquery.htm?Cn=A01)

## 4. 先把“因子”分成六种使用角色

| 角色 | 例子 | 应怎么用 |
|---|---|---|
| 可干预配置 | 解释版本、轮播配置、提醒计划 | A线的处理变量；保留真实分配 |
| 前置上下文 | 首次报价、分配前队列负载、历史客群 | 依据目标DAG决定分层、调整或效应修饰 |
| 中间环节 | LCP、重报价、补件、支付拒绝 | B线定位及机制诊断；估计整体改版总效果时不默认调整 |
| 外部事件/环境 | 政策适用暴露、竞品保障变化 | 范围匹配、事件研究；关联不自动晋升因果 |
| 结果/护栏 | 犹豫期撤单、到期批次续保 | 单独指标库引用；不得回填为同一销售过程的前置原因 |
| 测量质量 | SRM、重复、分母变更 | 先决定数据是否可用于解释；不是增长原因排名 |

角色依赖具体问题。例如历史已发生理赔可作为续保前上下文，但当前实验引起的客服咨询量是中介或结果。JSON的角色是建议默认值；正式 `FactorContract` 应绑定目标指标、处理和时间截点。

一个典型路径是：

```text
预先存在的渠道与产品结构 → 页面/报价/承保结果
解释配置 → 理解 → 申请 → 支付 → 承保 → 成熟撤单/续保
加载配置 → 运行质量 → 页面交互 → 申请
产品价格与资格规则 → 可报价/可售性 → 申请
采集与口径 → 观测到的曝光/点击/承保指标
```

“解释配置→理解→承保”中的理解是中介。若用处理后理解分组再算配置效果，可能破坏随机化。各环节条件转化率有诊断价值，但实验主结果宜以预先确定的合格分配单位为分母，并保留ITT。

## 7. 三个可执行的研究方案

### 方案A：报价到承保突然下降

先核查支付承保对账和分母版本，再按产品与渠道固定分层。将首次报价、最终报价、资格状态、核保队列和支付状态用申请级键串联，观察下降集中在哪一环。

预注册两个竞争解释：①同保障报价竞争力下降；②核保队列变慢。不能只筛选最后成功出单的申请；队列快照包含未结案单。价格数据若不可比，第一解释标记“不可检验”，不填合成竞品指数。

发现窗筛候选，冻结产品范围、时间窗与方向；确认窗做时间外验证。存在可信自然变化时才考虑准实验，并说明并行趋势、同期改价和申请构成变化。对我方可控的提交指引或进度告知另做随机实验；该实验只验证应对策略，不证明竞品或排队是最初根因。

### 方案B：解释页面优化是否值得上线

处理：完整条款和必要提示保持满足业务要求，比较两种已审阅的解释呈现；按用户稳定随机分组。

主指标：固定成熟观察窗内“有效承保用户/合格分配用户”。诊断指标：页面到达、理解题、申请提交、核保等待、支付成功。护栏：撤单、投诉、解释误解及性能。理解题建议对两组采用相同抽样机制并报告应答率，避免问卷本身引入不对称干预。

随机化前确定最低有意义效果、观察窗口、样本量和停止规则；用本地基准率和用户聚类情况计算，本文不虚构样本规模。整体效果用ITT；理解变化另列机制证据。若同时改变推荐方案数，需要因子化设计或分期实验，不能把组合效果拆归到某个组件。

### 方案C：续保下降的区分诊断

按到期批次建队列，先看续保报价变化、近期到期结构和此前服务体验，再比较“提前提醒计划”的随机分配。提醒提前天数由分配决定，不以打开日替代。

主指标为预定义宽限观察窗结束后的续保率；同步观察退订、投诉与提前续保时间。不能用尚未到期或观察未成熟的批次宣布流失。顾问共享时采用团队或适合的聚类设计，报告溢出风险。新客转化与续保分别建模。

## 8. 扩库后的统计策略

1. **先业务适用性过滤，后统计筛选。** 储蓄替代收益差只在适用产品研究，浏览器指标只在Web视图研究。DAG中的必要混杂变量不因单变量不显著被删去。
2. **预先冻结检验族。** 父因子、变换、范围、滞后、指标和交互都计入搜索清单。若机械将37条序列扩成75条，再沿用3种变换、32范围、29滞后，组合会从103,008升到208,800；这只是算术压力示例，本次38项中含类别和护栏，实际不应这样展开。
3. **避免机械派生。** 类别版本采用类别/事件编码；不对版本哈希求差。数值因子允许预设的后向变换，确认窗不再挑最佳滞后。低频月度宏观值日频重复不会增加独立信息。
4. **冻结可用时间。** `event_time`、`published_at`、`available_at`、`as_of`分开；仅使用截止时已可获得的数据。版本修订保留vintage，不能拿最新修订值回填历史回测。
5. **缺失不是零。** 未取得竞品报价、未交互INP、未回传支付和未成熟续保分别标原因。比例保留分子分母；分母为零返回缺失。滚动窗口与平滑都只使用过去。
6. **确认不能复用发现数据。** 时间外留出；重叠结局窗口必要时留间隔。重复客户、顾问和地区共振按实际依赖结构处理。时序检验依赖假设应在本地零效应及注入信号场景校准。
7. **相关聚簇不等于发现多个原因。** 报价慢、缓存未命中和超时可能属于一个故障链；先机制族再细分。不将父因子与派生重复计作独立证据。
8. **无提升允许入库。** 保存反证、失效范围和撤回原因；文献引用只支持研究动机。晋升需要本地测量验证、独立确认及适合问题的因果识别。

## 9. 接入现有工程的具体约定

本次不改统计核心和封装交付包，新增资料独立放在本目录。`候选因子库.json` 采用现有 `FactorRegistry.register_factor()` 可容纳的顶层字段，研究细节放入metadata，`license_ref=null`、`status=research_candidate`。每条定义可读取审阅，但现有默认检索只返回active，故不会误进入主检索。

注意两个当前实现边界：

- 当前 `production_eligible` 主要检查因子与证据许可字段是否存在。字符串“fixture-only”或“pending”不能证明生产授权，未来应增加来源类型、许可状态和数据成熟度显式校验。本次不靠填占位许可证绕过门禁。
- 当前快照聚合函数可根据输入快照生成序列；不能仅靠研究状态假设所有下游路径都自动拒绝。因此本包不附快照，也不提供自动激活操作。

建议的晋升顺序：`research_candidate → definition_reviewed → measurement_validated → eligible_for_discovery → independently_confirmed`；这些是建议的业务生命周期，不是声称现有代码已实现的状态枚举。因果结论仍沿用现有Claim Ledger。

上线前需要为每个被选中的因子补齐字段映射、负责人、实际许可、抓取/查询版本、内容摘要、可用时间、缺失机制和正式FactorContract。外部研究链接是**定义依据**，不是该平台的**观测证据**；二者应分库存放或用明确证据类型区分。

## 10. 执行批次与交付验收

| 批次 | 工作 | 退出条件 |
|---|---|---|
| 第一批：定义与质量 | 12项首批定义评审、6项质量指标采集检查、旧因子语义关系确认 | 主键、分子分母、时间语义与缺失原因可核对 |
| 第二批：业务近端 | 报价链、资格、核保队列、产品/客群结构 | 能从源日志重建值；按as-of回放一致 |
| 第三批：独立验证 | 选择一个解释呈现或提醒计划实验；B线冻结候选 | 有预注册方案和足够成熟观察；效果未知可报告 |
| 第四批：外部补充 | 同保障竞品数据、政策产品映射、适用宏观源 | 来源、适用范围、频率与发布时间可验证 |

不承诺四批能在固定四周全部结束；续保、撤单成熟期与企业数据接入会限制进度。成功标准也不是“库里条数翻倍”，而是：多少定义可测、多少快照可重放、多少独立确认、多少错误解释被排除，以及一次异常调查是否更快找到可验证的下一步。

## 11. 文献检索深度与限制

本次读取了法规、Google、W3C及Microsoft页面正文；部分学术来源使用作者/机构页面的索引摘要及搜索摘录，NBER正文访问返回403或抓取失败，PMC正文触发访问验证。因此没有声称完成所有论文全文或附录复核，也未采用未核实的系数和显著性。来源记录中逐项标注访问层级。若后续据此确定机制先验、样本量或准实验识别，需要进一步取得论文全文核对设计和外部效度。
