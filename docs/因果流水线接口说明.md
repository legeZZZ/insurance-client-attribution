# 因果图、识别与三轨定量接口

当前交付为可调用后端/CLI，控制台接入仍按要求暂缓。阶段B的A/B/C三轨、统计门与行动政策，以及阶段C的统一发布、持久调查与四层隔离编排已完成。

## 安装与执行

在代码包目录运行 `uv sync --locked`，使用已锁定依赖。

```sh
.venv/bin/python tools/run_causal_pipeline.py \
  outputs/stage_b/causal_foundation/requests/graph.json \
  --output outputs/my_graph.json

.venv/bin/python tools/run_causal_pipeline.py \
  outputs/stage_b/causal_foundation/requests/rct.json \
  --output outputs/my_effect.json
```

请求为 `{"operation": "graph|identify|randomized_effect|did_effect|controlled_series_effect", "parameters": {...}}`，parameters 对应下列 Python 函数参数。输入不合法时 CLI 返回非零退出码；证据不足属于正常 REFUSED 结果，效应字段留空。

## 图发现

`track2_v5.causal_discovery.discover_causal_graph` 消费规则日历与数值列。必须显式传 tau_max 及 response_window_basis。test_policy 运行前固定为 parcorr、cmiknn 或 both；both 会调用四路组合，不选最有利结果。CMIknn 的 shuffle_samples 与 shuffle_block_length 均写入清单。

变量集为 screened_candidates、protected_covariates、known_mechanism_nodes 的并集，经 parent_map 归并派生视图。输入缺失、构成确定性依赖或常量不能通过删掉保护变量来规避；需先处理输入契约。数值输入以完整规则面板为当前支持范围。

结果保存每路原始端点图、p_matrix、val_matrix、歧义、算法/检验分歧和一致方向的时间展开边。图结果只具有假设资格，不直接授予因果效应资格。样本量下限是执行检查，不是充分性保证；限制条件集也不提供 oracle 理论保证。

## 识别

`track2_v5.identification.identify_effect` 支持 RCT、DiD、BSTS、SCM、GCM、ITS 设计。checks 中每个条件包含 status 和 evidence_refs。supported 表示提供相应诊断/设计依据；部分不可由数据证明的条件允许 assumed 并在结果中标明 data_verifiable=false。

缺少必要条件、禁止调整变量、图歧义等产生原因码与补证清单。ITS 只允许探索预测；完全同期多干预只有 requested_effect=bundle 才可继续识别事件包。GCM 需要 accepted_dag，不会自动把 PAG 改为 DAG。

这是设计与证据契约检查，不是数据真实性认证。A轨已在估计前实际生成分配、SRM、成熟期及支持域检查；B轨基础估计器已生产趋势/对照/回测等检查；C轨已接入机制拟合/图和支持域检查。

## 随机实验估计

`track2_v5.quant_track.estimate_randomized_effect` 接收 rows 与 MetricContract。每行包含独立分析单位标识、treatment、outcome 及所需处理前协变量；聚类随机化额外提供 cluster_column，同组分配必须一致。

- ITT 不消费调整特征。
- CUPAC 使用训练组拟合的结果预测进行调整。
- AIPW 用预先指定分配概率和交叉拟合两臂结果模型构造分数。
- 所有同组观测进入相同折；标准化仅使用训练数据；方差按随机化组汇总影响函数。
- 必须提供分配记录引用、随机化声明、观测成熟时间与无干扰设计依据；缺失或失败不输出数字效应。
- randomized_effect 的rate分支要求每分析单位一个二元结果；已有 ratio_effect 扩展处理每单位分子/分母与聚类线性化，不应把不等分母比率塞入二元入口。
- 区间是逐项近似区间，不是自适应筛选后的同时置信区间，也不是后验概率。

输出包含 MetricContract、IdentificationReport 和 EffectEstimate，并绑定输入摘要与识别报告摘要。每次调用重新计算检查，不能传入旧报告跳过识别。

实际请求、四路图输出、正常 AIPW 输出及拒绝样例均在 `outputs/stage_b/causal_foundation/`。运行 `tools/check_randomized_tracks.py --repetitions 100` 可重现本批聚类随机实验评测。

## B 轨：共同上线 DiD、SCM、BSTS

三种估计器由 `track2_v5.quant_track` 导出，实现在 `track2_v5.observational_tracks`。JSON 新增 `did_effect` 和 `controlled_series_effect`。可运行请求及对应结果见 `outputs/stage_b/observational_tracks/requests/` 与上一级目录。

### DiD

`estimate_did_effect(rows, metric_contract, ...)` 接收完整日历的平衡面板，每行 `unit_id`（字符串）、`day`、`treatment`（当日实际暴露，0/1）、`outcome`。`intervention_day` 是共同上线日，MetricContract.window 必须恰好等于处理后估计窗口。重复或缺失单元拒绝；错峰、提前暴露或中途切换无法使用本估计器，返回 MODEL_MISMATCH。至少两个处理单位及两个对照单位；当前不支持跨单位聚类。

处理前每一天相对首日的组间变化差，计算 Bonferroni 同时区间；全部区间必须落入预先指定 `trend_tolerance`。这只是处理前等价性诊断，未来平行趋势仍要求 `parallel_trends_ref` 维持假设。`independent_units_ref`、`no_anticipation_ref`、`no_differential_shock_ref` 及每个对照的资格记录不可缺失。对照字典格式：`control_eligibility={"control_id": {"eligible": true, "unaffected": true, "evidence_ref": "设计依据"}}`。这些引用是调用方提供的设计依据，不代表系统认证事实。

估计使用每单位处理后均值减处理前均值，再比较两组变化；先在单位内合并天数，Welch 方差以独立单位为样本。count/currency 乘处理单位数和处理后天数，输出窗口总效应；currency_per_user 乘处理后天数；rate 要求每单位每天二元结果，输出等权单位的平均率差，不支持混入不等分母的日率或会话率。目标人群为这些处理单位，不能自动迁移到全公司。

### 受控日序列

`estimate_controlled_series_effect(days, outcome, controls, metric_contract, method="SCM"|"BSTS", ...)` 接收一个处理序列及预先固定的具名对照序列。当前只接收每日 count/currency 总量，估计汇总为窗口总效应；率和复合分母使用下文B_ratio扩展。全部对照需要显式资格记录，不能从候选根因中直接挑选。两个方法都要求 `relationship_ref`；缺失或污染均拒绝。

- **SCM**：至少两个供体；只用处理前数据拟合非负、和为1的凸权重。`prefit_rmse_limit`、`loo_effect_limit`（窗口总效应变化）、`max_weight` 必须预先指定。实际删除每一个供体重拟合，检查留一变化。另需 `no_spillover_ref`。区间以独立留出段的原始残差（保留均值）做循环块抽样，取总误差绝对值的95%分位构造对称误差包络；它是条件近似区间，不是供体随机分配的精确检验，也未覆盖选供体和权重估计的不确定性。`block_length` 默认5，`bootstrap_samples` 默认999且至少199。留出长度至少为效应窗口、20天和4个块长度中的最大值；不能以5天误差伪装充足的不确定性样本。
- **BSTS**：真实高斯局部水平随机游走 + 固定回归系数状态空间模型；Kalman 更新产生状态后验，处理后只预测、不吸收处理后的 outcome；累计区间使用完整跨天联合预测协方差。调用方必须预先指定 `observation_variance>0`、`level_variance>=0`、`prior_variance>0`。初始状态均值为0、协方差为 prior_variance×I；对照标准化仅使用本次训练段。此基础入口是固定超参数解析贝叶斯模型；下文B_BSTS_mixture实现有限超先验积分。不声称包含稀疏变量选择和全套CausalImpact，区间类型明确标注。

两者均实际留出至少一个完整效应窗口做处理前回测，RMSE 必须不超过 `backtest_rmse_limit`，并优于无对照基线至少 `min_backtest_gain`（默认0，要求严格改善）。SCM 基线为训练段末值；BSTS 基线为相同超参数、没有对照的局部水平模型。不能只通过宽松的绝对RMSE门而忽略对照预测力。

### 共通审计和限制

`observed_through` 必须满足成熟期。`simultaneous_interventions` 多于一个时，默认个体效应拒绝，只有 `requested_effect="bundle"` 能输出事件包 ATT。前移安慰剂采用固定种子，从唯一合法时点抽最多20个，每次只用该假时点之前的数据拟合，评价窗口完全处于真实干预前；不足20个如实返回 executed。安慰剂窗口可重叠，formal_pvalue=null，不宣称独立试验或多重校正。

结果继续输出 MetricContract / IdentificationReport / EffectEstimate。失败时 estimate/interval 为 null，保留诊断、原因码与补证条件。估计值的区间不处理自适应选择；错峰设计、比率序列、负对照与超参数扩展已由下文入口完成；本阶段统计矩阵已归档，跨业务全链路压力盲测属于T32。

重现本批初步校准：`.venv/bin/python tools/check_observational_tracks.py --repetitions 100 --output outputs/stage_b/observational_tracks/calibration.json`。这是三个固定生成机制，未筛选种子，拒绝数与全部逐次结果同时保存。

方法核对：[CausalImpact 官方假设说明](https://google.github.io/CausalImpact/CausalImpact.html)、[Brodersen 等原论文](https://arxiv.org/abs/1506.00356)、[Abadie 合成控制方法与适用条件](https://www.aeaweb.org/articles?id=10.1257%2Fjel.20191450)。实现范围以上述本地接口说明为准，不将论文完整能力等同于当前实现。

## 阶段 B 完成后的统一入口（2026-09-15）

`track2_v5.quant_track.estimate_effect(route=..., parameters=...)` 是三轨统一程序入口；CLI `operation="effect"` 使用相同参数。路线必须来自预先指定的研究设计，程序不会因为某个估计更显著而换路线。

| route | 实际执行 | 附加条件 |
|---|---|---|
| A | ITT / CUPED / CUPAC / AIPW | randomized_effect 原参数；CUPED 恰好一个处理前结果协变量，分组交叉拟合训练段估计线性调整 |
| A_ratio | 分子/分母线性化 ITT | 每分析单位 numerator/denominator，组级随机分配；按随机化组汇总比例影响函数；臂总分母为0拒绝 |
| A_forest | EconML CausalForestDML | honest=true，训练/推断按独立单位；聚类输入要求等大小组且协变量组内不变；查询不能超出已观察特征范围；探索 challenger 不直接成为行动依据 |
| B_DiD | 共同上线平衡面板 | 上文 DiD 条件 |
| B_staggered_DiD | 分上线批次的 ATT | 吸收式上线，完整平衡面板，整个目标窗口内从未受处理的对照；每批单独检验，跨批共享对照的影响函数先相加再求方差；不使用普通 TWFE，也不拿已经上线的批次作对照 |
| B_series | SCM / 固定超参数 BSTS | 上文受控日序列条件 |
| B_ratio | 配对分子/分母反事实 | numerator_controls 与 denominator_controls 各自资格检查；配对重采样留出残差，汇总 ratio_of_sums，保留分子/分母协方差；预测/重采样分母非正及不合法概率拒绝 |
| B_BSTS_mixture | 有限超先验 BSTS | hyperparameter_grid 每点有 observation_variance、level_variance、prior_variance、prior_mass；按处理前完整顺序预测似然更新权重，用混合CDF反解区间；不平均条件区间端点 |
| C | DoWhy-GCM | 合格的 accepted_dag、因果充分性/独立行依据、机制留出RMSE阈值和成熟期；图歧义、共线父机制、缺失依据或干预超出范围拒绝 |

所有单独的 operation 仍可直接调用：`association`、`graph`、`identify`、`randomized_effect`、`ratio_effect`、`causal_forest`、`did_effect`、`controlled_series_effect`、`staggered_did`、`bsts_mixture`、`ratio_series`、`gcm_effect`。

### 完整统计门与负对照

关联筛的 `confirmation_max_t_threshold` 默认20：冻结候选少于20时Holm，否则实际运行共享Y零分布的max-T留出确认。阈值在查看留出结果前指定，方法和候选数量写入清单。缺失/不足候选不被偷偷移除来减少校正。正式确认依赖时序零模型的适用性，实测FWER/FDP不等于有限样本理论保证；shadow始终单列empirical_only。

`negative_control_suite` 实际执行预先登记的负结果估计，再用区间是否完全落入预先指定等价容差进行检查。每项含 `operation`（did/series/staggered_did/ratio_series/bsts_mixture）、`parameters`、`tolerance`、`prespecified_ref`。输入 `primary_result` 与 `negative_requests`；输出保留全部负对照运行。失败使主结果效应/区间置空。`negative_controls` 还可消费外部已经产生且有引用的负对照区间；接口不将业务对照资格声明当作数据真实性认证。

### C 轨字段及不确定性

GCM 当前使用连续线性加性噪声机制；每个非根节点在旧/新数据分别做留出预测和父变量秩检查，随后真正调用 DoWhy `gcm.fit`、`distribution_change_of_graphs` 和 `average_causal_effect`。最多6节点进行精确子集Shapley；bootstrap至少20次，模拟至少200点，预算和种子归档。

`EffectEstimate` 是明确的旧人群干预 ATE。`mechanism_attribution` 独立包含 `functional=mean|variance|kl`、Shapley值、bootstrap区间、节点顺序和协方差矩阵：mean使用指标单位，variance使用平方单位，KL使用nats。它们不是贡献百分比，也不冒充ATE。区间是独立行bootstrap和模拟误差的条件结果；模型/图结构不确定性另外声明，未擅自平均PAG的多个定向。机制适用性依赖线性加性噪声和因果充分性；边际范围检查不认证任意高维人群迁移。

### 行动、因子设计和序贯停止

- `action` 消费合格三契约、业务阈值/单位价值/适用暴露倍数/实施成本，以及具有同时证据引用的全部护栏。输出补证、独立实验、保持基线、上线提案或回滚提案。探索森林/GCM结果只进入独立验证实验；不会自动改变流量。
- `experiment_proposal` 输出MDE、方差、不等分流、ICC设计效应和样本量；最低样本按独立随机化组计。因子实验当前按均衡主效应对比规划，alpha按因子数校正；样本预算与各实验臂合计一致。计划公式是固定终点正态近似，不能把它宣称序贯界限的精确功效。
- `experiment_designer` 输出所有阶数交互的alias及符号、二阶模型秩/可识别性，4因子为Resolution IV、5因子为Resolution V；不截断超预算矩阵。原主效应logistic估计器明确“省略交互”的模型假设。
- `factor_miner` 排序字段改为 `value_score`，并标 `investigation_value_not_probability`。后端 `validation_planner` 可传 `experiment_design_parameters`，将治理设计嵌入下一窗口实验提案。控制台字段消费按既定范围留待用户收尾。
- `sequential_policy` 预登记指标全集、检查点、最低样本、成熟期、期限、alpha及可选 `stopping_rules`（primary、threshold、guardrail_limits、allow_futility）。`checkpoint` 读取累计两臂 n/sum 和上一状态，只允许递增登记检查点与样本量；策略摘要改变、重复检查、终态继续检查均拒绝。
- 序贯界限为有限检查点×指标×两臂的Hoeffding联合界限，要求独立且取值在[0,1]的分析单位，或先汇总为独立聚类均值；不允许把原始相关会话当成独立用户。输出 STOP_SUCCESS / STOP_HARM / STOP_FUTILITY / STOP_DEADLINE / CONTINUE。停机仅停止监测建议，实际流量仍通过既有审批平台执行。

阶段 B 的实现及约定数据设计验收已完成；统一发布账本与四层隔离编排在阶段C完成；真实业务全链路盲测仍属于阶段E。任何估计器都不承诺对任意非平稳、未测混杂、自适应选择或不可识别设计产生有效因果结论，输入超出支持范围时明确拒绝。

全部可复制请求、实际CLI输出、测试日志、统计矩阵与源码摘要位于 `outputs/stage_b/completion/`。依赖已锁定 DoWhy 0.14 和 EconML 0.17.0；不需要控制台接入即可运行。

## 阶段 C：发布、调查与持久证据接口

新增 `operation=pipeline|investigation|factor_registry`，继续使用同一 CLI：

```sh
.venv/bin/python tools/check_stage_c_acceptance.py
.venv/bin/python tools/run_causal_pipeline.py request.json --output result.json
```

完整请求与输出见 `outputs/stage_c/completion/acceptance.json` 指向的 `run_directory`。验收请求使用已声明 fixture；正式使用时替换数据和设计登记即可。源声明被记录，不开展外部真实性核查。

### 统一后端入口

`scenario_reports.run_causal_investigation(request, runtime_dir, timeout=60, baseline_bytes=None)` 是新调查的主后端入口；CLI `pipeline` 调用同一个函数。request 包含 `route`、`parameters`（阶段B三轨原参数），可带 `baseline`、`association`、`publication_options`。四层均实际启动隔离进程，L0 只接收指标和可选登记基线，L1 只接收关联数据，识别/L3 接收本路估计所需数据。层间核对 stage、前项摘要、输入摘要和输出摘要，不接受模块名、任意工具或对话历史。

有 baseline 时执行 `attribute_baseline`；有 association 时执行关联发现与留出确认。预登记实验无需先挑候选，L1 返回明确跳过计算的账本项。识别层复用三轨已有的数据诊断，丢弃估计数值；L3 重算后核对同一识别摘要，避免外部报告冒充当前数据资格。该实现会重复部分诊断/估计计算，耗时如实进入账本。

`publication.publish_conclusion` 分开生成 identification / statistical_uncertainty / action_policy，校验指标、识别及效应契约并生成结论文字。实际等价、区间仍不确定、不可识别和探索后待独立确认使用不同解释。六种展示类型为 DESCRIPTIVE_FACT、CANDIDATE_ASSOCIATION、CONDITIONAL_TEMPORAL、OBSERVATIONAL_EFFECT_UNDER_ASSUMPTIONS、RANDOMIZED_EFFECT、COMPONENT_RANDOMIZED_EFFECT；六个拒答码沿用 contracts.REASONS。

`ClaimLedger.add_claim(..., contracts=...)`、报告生成/缓存读取/Markdown、两份后端 foundation 的 artifact/evidence pack 发布均接入发布门。旧无契约强因果标签降级并撤下对应因果数值；老 Bayes/组件计算可以保留为诊断，不能仅凭字符串或 design_record 布尔值获得已识别结论。新 run 保存 SQLite 证据引用，`read_run` 和发布门读取时重新检查资格；撤销后返回 DATA_INVALID 和重算指引，原始内容仅供显式审计读取。

### 持久注册表与循环

`investigation` 参数为 `{db_path, action, parameters}`。允许：revise_resource、invalidate、register_hypothesis、snapshot、audit、read_asset、create_loop、create_loop_from_factors、step_loop、finish_loop、run_loop、recover_loop、read_loop。它是受信任的后端管理 API；模型只可提交下述六类 proposal，不能调用证据管理操作。

- SQLite WAL/事务保存不可变证据、版本指针、依赖边、假设、循环和 holdout 消费记录。更正命名数据/快照后，依赖统计失效、结论撤销、技能暂停，假设后代同时失去资格。
- 假设快照包含结论类型、识别状态、不确定性、检验历史、止步门和终态。supported/refuted/dormant 由实际证据或调查中止决定，模型不能写状态；refine/merge 的父假设必须先通过门，后代统计必须依赖对应父证据版本。
- `create_loop` 接收命名数据资源（days/residual/factor_series）和冻结 config；末尾20%为 holdout，默认隔离带至少 `max_lag+smoothing_window+2`。最多三轮，无证据进展即结束。
- `step_loop` 的 proposal 仅允许 ADD_HYPOTHESES、SYNTHESIZE_FACTOR、ADJUST_THRESHOLD、CHANGE_CONDITION_SET、QUANTIFY、STOP。合成动作按原方案 P3 roadmap 保持禁用。阈值可提案，正式确认使用历史最低筛选阈值下冻结候选并集，不能改 alpha、时间窗或预算。
- 正负 lag、每次探索和实际图 CI 检验全部计数。图调用可提前耗尽 CI 预算；失败和中断保留已消耗预算。最终确认先持久消费 holdout 并记账，再读取/计算；失败、重启、换 seed 都不能重复窥探同一命名来源的重叠窗口。
- 中间 q 值仅属探索，不宣称自适应 FDR 保证。最终独立 holdout 小族 Holm / 大族共同 max-T；其完整时间依赖校准仍属阶段 E。只读重放已完成状态不会再次执行检验。
- QUANTIFY 只能引用 config 中预登记、独立于搜索的定量请求资产，具体识别仍由三轨计算判断。直接 RCT 可以不消费搜索 holdout。

`SkillStore.bind_evidence(name, version, registry, dependencies)` 将实际技能版本绑定到持久证据；`active`、`activate`、`rollback` 都会检查，失效时原激活版本停止返回并记暂停日志。阶段D已通过下述治理入口接通技能结晶、独立评审和人审发布。

### 本地模型与成本

`LocalPolicyAdapter(endpoint=None)` 默认完整规则模式。可显式传本机 HTTP 兼容 `/v1/chat/completions` 地址和 model；总调用时限由独立传输进程控制，超时杀掉传输进程，非法 JSON、越权动作、不可用因子、过大响应均进入规则兜底。模型只看到结构化快照和候选ID，不接触最终 holdout 原始值。provider 的 usage 有则记录，缺失记未知。

四层无模型 worker 的模型 token 为0。cost_ledger 记录每次真实 I/O 字节、耗时和 PID；默认单层基准是序列化请求大小，可显式登记 `baseline_bytes`。累计字节超过4倍基准，剩余层在一个新进程内顺序载入，仍执行相同门禁。字节比率不冒充 token 比率；这也不是操作系统级安全沙箱。

### 因子来源与下一窗口

`factor_registry` 操作包括 intake_next_window、intake_adapter、retrieve、history。人工反馈和外部 `adapters.intake_factor_series` 均接入下一搜索窗口，保留原名称/来源、别名、许可证、完整摘要、可用日、版本及派生谱系。因子、证据和快照修订追加历史；批次原子提交。

正式检索必须同时传 as_of 和 search_window，过滤未可用/未到窗口数据；旧无时点查询不会带出排队中的补充数据。具备完整声明的因子通过 FactorContract 校验。没有足够契约的条目可作为目录信息，但 `create_loop_from_factors` 仅采用契约有效、来源许可齐全且与面板完整对齐的快照，并绑定来源快照依赖。检索不改变后验、不授予因果资格。

来源修订后调用 `export_window` 或重新 `create_loop_from_factors`，命名快照的新版本会使其下游旧统计/结论/技能失效。审计历史保留，原失效摘要不能被重新写入来复活。


### 阶段D：技能、反馈、先验与常驻扫描

沿用 `tools/run_causal_pipeline.py request.json --output result.json`。请求格式为 `{"operation":"skills|feedback|scan|prior","parameters":{"db_path":"state.db","action":"动作名","parameters":{}}}`；四类入口共用同一SQLite注册表。逐动作完整可运行请求/输出见 `outputs/stage_d/completion/acceptance.json` 所索引的55个CLI案例。

| operation | action | 持久行为 |
|---|---|---|
| skills | capture、trace、propose、get、review、freeze_suite、validate | 成败轨迹、修正证据与负例、delta/冲突、skill/2 schema；独立作者审查并实际重放；冻结配对任务消费与非劣/关键护栏检查 |
| skills | approve、publish、retrieve、replay、monitor、suspend_scope、rollback、learn_from_feedback | 凭证绑定、最多10%首发、独立灰度监测后扩大；适用域/窗口/任务分桶/版本检查；失败降域、旧版本回滚；告警反馈转方法候选 |
| feedback | submit、read、queue、register_supplement、calibration | request_id幂等、修订supersedes、候选确认/否决与补充、下一窗口因子登记、告警有用/误报标签；标签不能提升因果资格 |
| prior | observe、prior_for、estimate_rate | 有版本的数据资产绑定、历史任务/数据去重、上下文与时间匹配、遗忘/伪样本上限/预测错配降级、实际Beta–Binomial后验 |
| scan | configure、start、launch、stop、status、tick、recover、alerts、confirm | 冻结作业配置、独立常驻进程、租约恢复、预算先扣、水位/新鲜度/告警去重、独立下一窗口确认 |

`capture`只接受数据资产对应的真实请求；支持 `check_metric`、`check_overlap`、`estimate_effect`、`scan_window` 四个可执行方法。失败有可执行修正才可结晶；环境问题输出ISSUE、未证实经验AUDIT_ONLY、重复或非新增收益NOOP。独立审查人不能是轨迹作者。冻结验证任务与数据必须独立于提取数据及所有已消费验证，执行前持久消费；相同已完成验证只读返回NOOP。灰度套件不能复用初始套件或其数据。

`approve`要求非空approver/credential_ref，绑定name/version/spec_digest/suite_ref；人审身份由受信管理后端提供。当前CLI验收使用显式fixture凭证，不代表生产身份认证。新套件监测后需重新绑定审批才可扩大发布。主SkillStore标记governed后，旧activate/rollback不能绕过治理。来源、验证数据或当前兼容证据失效后，检索降为审计用途，实际技能停止执行。

独立进程重放绑定task_id/data_ref/skill_ref，校验输入输出摘要并设置总时限、输入输出大小与允许操作。`claim_ceiling`约束当前结果，当前强因果结论仍需主流水线重新识别。这里的进程隔离不是操作系统安全沙箱。成本记录真实I/O字节、耗时与PID，无模型调用的model_tokens=0。

先验仅消费匹配metric/population/assignment_version的较早期观测。历史伪样本最多为本期样本的25%，99%先验预测区间错配时不使用历史贡献；方法检索不进入数值先验。`estimate_rate`输出描述性后验区间，无因果资格。

扫描配置提供input_path、interval_seconds、max_staleness_seconds、test_budget、lifetime_test_budget、timeout和error_policy；具体参数约束见`ScanService.configure`。`start`启用作业，`launch`启动实际resident worker，`stop`停止后续轮次；正在执行的有界轮次可完成后退出。输入按days水位消费，旧窗口修订使旧证据/告警失效，不重复发布旧窗口。中断/失败保留预扣预算，租约恢复可重试但不能清空累计预算。反馈只影响下一窗口的优先级与预算分配，不改历史统计量。

`run_c_line`支持metric_series，多个metric_id必须各有响应；`confirm`同样要求此映射，不能串用响应。持久/起始/脉冲效应采用不同证伪适用性；样本不足或预算耗尽明确降级。默认exploratory_only不发正式显著性声明；显式alpha_spending_empirical使用总alpha/[n(n+1)]及冻结族Holm，确认前消费非重叠窗口并记账。经验块零模型的全局时间依赖校准仍由阶段E完成，WATCHLIST或FACTOR_CANDIDATE均不授予因果资格。
