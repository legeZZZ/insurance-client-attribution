# 阶段E/F后端交付与迁移说明

当前主入口为 `tools/run_causal_pipeline.py`，共享引擎为 `track2_v5`。旧场景演示保留作历史回归，不以其旧枚举代替统一证据门。全部控制台页面、浏览器联调及控制台鉴权仍由用户收尾，本说明不涉及界面操作。

## 运行与部署

```sh
scripts/run_backend.sh examples/backend-smoke.json --output outputs/smoke.json
.venv/bin/python tools/run_backend_tests.py
.venv/bin/python tools/check_stage_e_acceptance.py
.venv/bin/python tools/check_stage_f_acceptance.py

docker build -f Dockerfile.backend -t track2-backend:stage-ef .
docker run --rm track2-backend:stage-ef --help
```

实际后端容器使用独立CLI入口和非root运行用户；`Dockerfile`及原compose属于旧控制台部署，未替换。Dockerfile.backend根据uv.lock选择本平台wheel或源码包，下载时核对原始SHA256，再构建wheel。`requirements.lock.txt`由锁文件导出；源码构建的wheel具有新摘要，以实际wheel集合的SHA256SUMS为离线安装依据。

已提供 `outputs/stage_e/deployment/wheels-linux-arm64.tar`。在Linux ARM64匹配环境解包后执行：

```sh
tar -xf outputs/stage_e/deployment/wheels-linux-arm64.tar
scripts/install_offline.sh wheels /path/to/new-venv
```

安装脚本先验证完整wheel集合及摘要，再使用 `--no-index` 安装并运行 `pip check`。其他平台执行 `scripts/make_offline_wheels.sh /path/to/wheels` 生成本平台离线材料；不能把Linux ARM wheel用于其他架构。交付验收包含容器禁网状态下新建环境、从wheel安装和实际因果后端请求，不仅是安装命令展示。

## 企业接入与双域配置

`enterprise`操作参数：manifest_path、as_of（整数日）、runtime_dir。配置schema为enterprise/1；source保留声明的source_uri、license_ref、timezone、available_day，不核查真实性。源列到标准列的field_mapping在载入时执行，列覆盖/重复单位/非有限值/未来数据/不成熟窗口拒绝。

- A：observations行级实验表（unit_id、treatment、outcome，可带声明的实验前协变量），经相同A轨与四层发布门。
- B：panel/changes/external_events/factors进入覆盖率解释账本及主动扫描；也支持明确的B_DiD/B_series等已登记定量路由。
- C：panel residual/factors进入扫描；已接受DAG的定量任务可显式选择route=C，仍执行原GCM识别门。
- 六份可执行配置：examples/domains/insurance与examples/domains/ecommerce各含A/B/C.json。两域只改指标名、来源声明和因子配置，算法相同。
- external_adapter的N1是只读授权文件因子导入下一窗口；N2复用LocalPolicyAdapter的本地模型/规则兜底与动作schema；N3实际执行sandbox创建/5%灰度/指标/护栏暂停流程，无生产流量副作用，production请求拒绝。

换真数据时保留schema和字段映射，替换表路径与声明、分析时点；重新生成输入摘要。命名资源修订会使旧下游证据失效，不能复用旧结果当作新输入的结果。

## 盲测后端

operation=blind，参数为db_path、action、parameters。动作依次freeze → run → reveal → report，read可随时读取；CLI完整样例在E验收目录。

freeze接收case_id、请求（pipeline/association/effect/scan_window/graph）及protocol（frozen_by、analysis_as_of、truth_scope）。结果必须由真实执行冻结后才能reveal；失败结果也冻结，不允许看到真值后重跑同一case。真值复核人必须不同于冻结人，提供事后evidence_ref。输入、结果、预测和真值分别保存摘要及SQLite依赖。

真值分开提供marginal_dependence、conditional_relevance、graph_edges、intervention_effects、changed_mechanisms。null表示未知，[]表示已知为空；未标注项不当成真零。效应表须有effect与identifiable；其余表逐条标positive。工具按实际输出语义评分：边际关联不能替代条件相关，图边不能替代干预效应。真实Y加针只能使用增量目标/已知标签；不能把其他因素全设为零。后期真实2–3业务案例按同流程替换输入和事后真值即可。

## 研究能力和默认状态

`knockoff_research`运行Gaussian构造、行/时间联合交换性诊断、ridge系数差flip-sign、子采样e-value均值和e-BH。所有输出仅用于研究；formal_selection_allowed与causal_eligible均为false。IID已知联合模型下的条件资格单独标注；近似协方差或时间子采样不等同理论条件成立。详细研究结果见阶段E-F评测报告。

`synthesis`使用db_path/action/parameters。configure默认enabled=false；set_enabled仅切换开关，不重置累计记录。propose只接收类型化AST：factor叶子，add/subtract/multiply/divide/lag/rolling_mean；禁止eval、负lag、单位冲突、零分母以及超出深度/节点/候选预算。current_window在此接口表示提取数据最后可用的整数日。

freeze锁定整个生成族（包括弱候选）；confirm必须提供新的有效数据资产，时间晚于原窗和隔离带。完整族Holm确认，跨确认次序采用可求和alpha额度，前置消费窗口、失败保留预算，不能改名或换策略复用同一重叠窗口。晋级最高为FACTOR_CANDIDATE，源数据更正后WITHDRAWN。此受控实验入口独立于生产LoopController；生产策略的SYNTHESIZE_FACTOR继续禁用，不进行强化学习训练或统计核心自改。

## 迁移与证据

新增SQLite表以CREATE TABLE IF NOT EXISTS增量创建，不删除原数据。正式切换前使用SQLite backup API制作一致性备份，或停止写入并完成checkpoint后复制数据库；不要直接复制正在写入的数据库/WAL作为一致性备份；可先用新runtime_dir重放历史请求。新技能使用治理版本绑定，旧技能记录可审计但不能绕过审批与当前证据有效性检查。

历史阶段A–D的manifest是当时快照；本次继续修改累计文档后，旧摘要自然与新文件不同。当前源代码与交付文件以E/F最终manifest和发布包SHA256为准。各阶段完整测试、CLI请求输出、协议、逐种子结果和失败记录均保留。
