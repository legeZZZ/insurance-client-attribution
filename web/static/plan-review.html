00.1 · SKILL EVOLUTION GOVERNANCE

技能进化治理：RSI 从轨迹找方法缺口，自进化把补丁受控发布

评审的重点不是“模型会不会自己变强”，而是每条经验能否被追溯、限制、复验、发布和撤回。

案例：旧技能遗漏外部暴露核查，曾把共同冲击误写为“版本导致下降”

先看常驻的 G0–G6 治理台，再播放双源轨迹和递归回流。播放由评审者主动触发，避免自动播放与审查阅读互相抢占。

RSI ≠ 自改模型
RSI：从轨迹找“方法缺口”成功与失败一起进入；产物是“下一次先核验两组外部暴露”，不是复用“版本是根因”。
自进化：把 patch 受控变成 skill版本化 schema、独立审查、冻结验收、人工审批、10% 灰度、可按作用域暂停。
统计参数记忆：另一层能力跨期 Beta 先验与漂移监测，不等于技能结晶，收益也必须分开报告。
常驻审查台：先看每个门关住什么，再播放双源轨迹如何触发补丁。

动态仅演示真实发生变化的两件事：双源轨迹进入 G0，以及不满足门禁时被导向 G6/人审。虚线表示已经发生、仍应保留以便整体复盘的历史交接。

递归闭环审查：RSI 的“递归”到底在哪里？

递归不是模型修改自己，也不是一次 patch 通过后就结束。递归发生在“已发布 skill 被下一窗口重新调用”之后：新的任务结果、失败轨迹或人工反馈会再次成为下一轮技能演进的输入。

C-line alert / human feedback → learn_from_feedback(event_id, skill, context) → capture(task_id, data_ref, operation, author) → propose(trace_ids, applicability, claim_ceiling) → review → freeze_suite + validate → approve → publish → next-window retrieve() + replay() → new trace / feedback → G0 again

递归更新的对象：调查步骤、前置条件、验证模板、适用域和告警预算。不递归更新：max-T 联合零分布、AIPW 标准误、IdentificationReport 识别门、历史因果答案和真实流量权限。

因此“技能越用越强”必须以跨窗口新任务验证为证据，不能用同一批 holdout 反复自证。

放大一：捕获与审查隔离，代码里到底如何实现？

SkillGovernance.capture() 固化 task_id、版本化 data_ref、context、operation、author、replay 和 evidence；同一任务/数据/操作/上下文/作者的 digest 重复捕获会幂等返回。

reviewer != any(capture.author) subprocess.run(python -I skill_worker.py) OPS = {check_metric, check_overlap, estimate_effect, scan_window} binding + input_digest + worker_digest 必须一致

审查者会重新回放选定操作；worker 有输入/输出/超时上限，且报告 no_code_execution、no_traffic_mutation、fresh_evidence_only、no_causal_without_identification。

真实边界：这是角色分离 + 新解释器进程 + 固定操作白名单；不是 OS 级沙箱，也不是独立代码库或独立模型的审查。

放大二：ACE delta 如何避免“整段上下文重写”？

propose() 只接受可检查规则：when、action、evidence、polarity。候选适用域不得比源轨迹更宽，claim_ceiling 不得高于最弱源 replay 支持。

v4 rules + { added_rules, previous_digest, base_version } -> v5 相同 trigger 不同 action -> conflict -> AUDIT_ONLY 与 active rule 冲突 -> 必须精确 digest replacement 否则排除冲突，不用多数投票覆盖旧规则

这就是 ACE 在本项目中的落点：保留旧版本、来源和替换绑定，只把验证后的差分并入 schema，降低整体改写导致覆盖历史的风险。

它降低 context collapse 风险，不等于自动证明模型永不遗忘。

放大三：G5/G3 为什么不会“验证通过就直接上线”？

  • freeze_suite() 至少 2 个独立 task；冻结后验证任务和数据先被消费，不能换名字复用。
  • validate() 做 base/candidate 配对 replay：关键任务失败零容忍，增益须不低于容差；通过后仅变为 trusted，仍 execution_eligible=false。
  • approve() 要独立人工凭证，捕获作者不能批准自己。
  • publish() 首发不超过 10%；扩大必须用新的 canary suite 监测并重新绑定审批。
  • retrieve() 还会检查当前数据有效、scope、窗口、trusted、灰度 cohort；否则仅 AUDIT_ONLY。

失败归因与人工何时进场？

不是“失败就再反思一次”。G6 先区分是技能问题、无增量、证据不足，还是环境/源问题。

同 trigger 不同 actionsource evidence invalidholdout critical fail想扩大 >10%重放失败可归因

冲突和缺证据留在 AUDIT_ONLY；环境超时输出 ISSUE；可归因的重放失败才允许 suspend_scope() 缩域。涉及发布、扩大灰度、回滚、不可观测业务事实时，转人工节点。

进化收益账本：两类“变强”不能混算

技能方法记忆 / RSI 自进化：当前是严谨评测设计，不是已公布增益

三组：无记忆 / 仅检索 / 有门禁结晶；固定模型、工具、预算、难度、缓存政策。分别记事实正确、数值正确、证据资格、合理拒答、行动可执行、错误因果断言率、人工介入、命中/耗时，以及检索、审查、验证、失败重试、重放的全链路 token/延迟/成本。

报告方式：配对任务损失 + 置信区间；另列一次性结晶成本与成功重放边际成本。当前 isolated replay 已记录字节和耗时，model_tokens=0，不能把它说成已有 LLM token 收益。

统计参数经验记忆：已有 7 窗口消融，但不是技能结晶收益

Beta 先验 + decay + cap + PID 调 shrinkage：低流量窗口 ATE RMSE 从 0.004509 到 0.004019，相对改善 10.9%；富数据窗口从 0.000491 到 0.000642，反而变差 30.8%；spurious moderation 改善仅 0.4%。

诚实边界：错配报警在 seed 601 起点触发，后续会随 store 衰减适应；这不构成持续检测证明，也不能替代技能层三组盲测。

当前评审结论：已经具备什么，仍缺什么？

已具备的可核查机制：G0–G6 核心代码、版本化 skill/2、角色分离、固定 worker、delta 冲突排除、冻结配对验证、批准/灰度/缩域和回归测试。

仍需明确的工程边界：独立审查不是独立实现；方法记忆三组真实盲测尚未报告；参数记忆仅覆盖 7 个模拟连续窗口且富数据有损；10% 灰度是受控机制，真实生产身份与流量平台接入属于后续落地。

四类借鉴的落点：OpenSpace 对应捕获/审查隔离与 trust 生命周期；ACE 对应 schema delta 与冲突不投票；HugAgentOS 对应“技能不能越过当前识别与 claim ceiling”；SkillClaw 对应冻结验收、非退化护栏、灰度与回滚。借鉴的是治理机制，不把论文名当作功能已经天然成立的证明。

02 · STATISTICAL FOUNDATION

传统统计方法各自做什么

算法不是“越复杂越高级”，而是对不同数据条件承担不同职责。

率值异动：先解释“变在哪里”，不急着解释“为什么”

Δ rate = rate component + mix component + interaction component
必须满足：rate + mix + interaction = observed total change

rate：同一人群/切片自身的转化率变了；mix：人群、渠道或版本结构占比变了；interaction：率变化和结构变化共同作用。闭合不了就报告“分解失败”，不能挑一个好看的分量。

L1：max-T + holdout

因子 × lag 的大量搜索会产生偶然显著。检验族原子键全量记账，同一批 moving-block 重排同时服务所有候选，得到联合零分布；前窗口探索、末窗口封存，最终候选必须复现。

诚实边界max-T 只在声明的零模型、时间结构和适用条件下提供控制，不是对任意非平稳数据的无条件保证。

L2：PCMCI+ / LPCMCI

用条件独立检验逐步删边，再同时条件化源和目标的父节点，压制自相关与共同驱动。LPCMCI 对无法定向的边保留圆端点，输出“方向未定”，不硬猜因果方向。

识别门：方法由数据设计决定

数据/设计条件优先估计路径失败时交付
随机分配、完整实验日志ITT → CUPAC/AIPW；必要时 CATE实验完整性与功效诊断
处理组/对照组 + 前后期DiD，检查平行趋势描述性差分或不可识别
事件时点 + 稳定对照BSTS / CausalImpact / 事件研究CONTROL_CONTAMINATED
少数处理单位 + 供体池合成控制对照不可靠
单条前后序列ITS，仅模型条件下预测差不渲染因果效应数字
业务 DAG + 机制数据DoWhy-GCM 分摊封顶 OBSERVATIONAL_EFFECT_UNDER_ASSUMPTIONS
外部冲击的关键边界只有共同冲击以近似相同幅度作用于处理组和对照组、且两组测量口径稳定时，才可能在 gap = treated - control 中抵消。暴露不均衡时，差异效应仍可能留在 gap/residual 中，必须单独验证，不能机械地再从残差里扣一次。

三态分离：不显著 ≠ 可忽略 ≠ 不可信

不显著

估计值可能不为零，但区间很宽，说明精度不足。

可忽略

区间整体落在预设实质等价界内，支持“影响足够小”。

不可信

识别或数据前提不满足，不渲染效应数字，给补证路径。

02.5 · CONTRACTS & ACTION POLICY

六契约：把“严谨”变成程序检查项

每个结论都先通过输入、设计、检验、识别和效果对象的契约。

契约固定什么防止什么缺失时

五条纪律，防止“越查越偏”

每次反馈绑定 request_id，幂等写入 Claim Ledger；修订通过 supersedes 指向旧条目，而不是覆盖历史。新增业务事实以 source=human 进入 Factor Registry，带时间、范围、凭证和操作者。

哪些场景必须人工

  • 关键业务事实缺失或只能由人确认；
  • 新技能改变适用域或 claim_ceiling；
  • 证据冲突、依赖失效、多次错误归因；
  • 技能发布、扩大灰度、回滚和高风险生产动作；
  • 需要判断不可观测业务事件，而数据无法编码。
评审边界人工确认是事实和风险的补充，不是统计证据的替代。人工说“那天确实发过短信”，只能让系统把短信纳入下一轮候选和验证，不能直接把短信升级为“导致下降”。
07 · C-LINE RISK DREAMING

C 线风险预演：先问“什么会把指标推过红线”

“做梦”不是预测未来，而是把候选风险变成可计算、可证伪、可前置监控的情景。

先把概念说准：AI 做梦 = 受约束的风险预演器

现有 C 线是“现实出现信号后，猎手扫描因子 × 指标 × lag，再交给证伪者”。升级后，Agent 先在 191 个研究候选因子中构造尚未发生的风险情景，再调用现有统计线路计算：如果某个因子在给定范围、时间和暴露条件下恶化，指标是否可能越过红线；如果可能，最早能看到什么脚印。

必须守住的边界大模型只负责提出结构化情景和调度研究动作；反事实计算、区间、识别条件、回测和放行仍由确定性统计程序与证据门完成。输出是“条件于模型的风险预演”，不是“未来一定会发生”，更不是自动生产动作。

用一个项目案例走完整个预演流程

观察到：版本切换后转化率下降。旧技能很容易把“版本”直接写成根因，但 C 线升级后会并行提出至少三类梦，并把共同外部冲击、两组暴露不均衡和测量口径变化列为可竞争解释。

步骤系统做什么可交付物
1. 生成情景从因子库选择“落地页版本、同保障报价差、核保队列年龄、支付失败率、竞品报价变化、分流比例失配”等候选；每个情景绑定时间窗和适用域。scenario_id + 假设 + 证据引用
2. 并行推演梦 A：版本改变理解或提交；梦 B：竞品/外部冲击对处理组暴露更强；梦 C：核保或支付环节变慢。分别用适配的三轨估计影响和区间。多情景影响区间，不投票抹平冲突
3. 反向压力给定“转化下降超过 θ”的业务红线，反推各因子需要恶化到什么幅度；优先检查可观测、可干预且离红线最近的组合。风险排序 + 临界坏幅 + 约束
4. 找最早脚印若梦 B 成立，优先盯同保障报价差和竞品报价变化；若梦 C 成立，优先盯核保队列 P90、补件和支付失败，而不是等最终转化掉完。领先指标、阈值、告警预算
5. 证伪与回放用负对照、安慰剂、lead-lag 反转、时间外 holdout、外部暴露强度和口径稳定性验证；失败的梦进入负例库，杀不死的才留在 WATCHLIST。WATCHLIST / NEGATIVE_EXAMPLE / AUDIT_ONLY
外部冲击不能机械扣除只有共同冲击以近似相同幅度作用于处理组和对照组、且两组测量口径稳定时，才可能在 gap = treated − control 中抵消。暴露强度不同时，差异效应仍可能留在 gap 或 residual 中，必须单独验证。

Agent、统计引擎和门禁的权限边界

组件负责什么不能做什么现有实现 / 新增增强
Dreamer 子 agent从因子库组合情景、指定目标和验证计划、安排预算不能创造未登记因子、编造观测值、宣布因果或下生产动作可复用主 Agent / Factor Registry；新增 scenario schema
统计推演器执行干预估计、区间、反向搜索和时间外回放不能绕过 MetricContract、IdentificationReport 和 claim ceiling复用 BSTS / SCM / GCM 三轨；需补 scenario runner
证伪者主动尝试杀死梦：负对照、安慰剂、lead-lag、holdout、稳定性“杀不死”不能直接升级因果复用 watchlist_scan / temporal_shadow_stability
证据门把梦降级为监控、验证提案、审计或拒答不能让大模型多数投票越过识别门复用 IdentificationReport / Claim Ledger
RSI从成功与失败轨迹中更新调查步骤、前置条件、验证模板、适用域、告警预算不能把某次梦境的真实与否写成永久因果答案复用 skill_evolution / replay / experience_store

“预知”具体靠什么，如何验收

提前量从“指标已经下降”提前到“上游脚印异常”，报告平均 lead time、分位数和提前量稳定性，不只看相关系数。
误报代价同时记录 false positive、告警预算和人工处理成本；领先但每天误报的信号不能直接上线。
时间外存活确认窗和下一窗口才算真正验证；同一批 holdout 不能被反复拿来证明梦越来越准。
可验收的核心指标风险情景命中率、平均提前量、时间外 precision/recall、负对照误报率、区间覆盖率、越界率、每次有效告警成本，以及从告警到可执行验证提案的耗时。

和现有猎手/RSI 的真正闭环

Factor Registry → Dreamer 生成风险情景 → 统计推演 / 反向压力测试 → 领先指标进入猎手
→ 新窗口观测 + 证伪回放 → WATCHLIST / 负例 / 审计 → 成功与失败轨迹进入 RSI
→ 只更新调查方法与预算 → 下一轮 Dreamer 更少重复搜索、更早触发验证
递归的是“如何调查”，不是“事实答案”；统计核心、识别门、claim ceiling 和生产权限保持不变。
当前工程诚实口径现有代码已经具备因子注册、候选扫描、证伪、WATCHLIST、识别门、三轨估计和回放等承接点；“Dreamer 情景生成 + 反向压力搜索 + 领先指标编排”仍应标记为设计增强项，不能把这份升级方案写成已经完成的生产能力。第一阶段建议只做 3–5 个手工情景回放，先证明情景能被证伪、脚印能在时间外成立，再扩大搜索空间。

验收不是只看“答对率”

  • 候选误报：mean FDP、功效、发现数量，完整重跑预处理到选集；
  • 图与识别：错定向率、错误因果断言率、拒答率、有效任务覆盖率；
  • 效果区间：Bias、RMSE、覆盖率、区间宽度，整体和选择后分开统计；
  • 循环纪律：FDR 记账、轮次上限、单调性停机是否真实触发；
  • 自进化收益：无记忆 / 仅检索 / 有门禁结晶三组配对比较，并扣除治理成本；
  • 系统成本：token、字节、耗时、失败重试、重放全链路计入。

五份“真值”不能混用

评测至少区分 marginal_dependence、conditional_relevance、graph_edges、intervention_effects，异动归因另有 changed_mechanisms。不能拿相关性答案去判因果模块，也不能把“用户接受结果”当因果真值。

半合成数据的诚实口径真实 Y 上直接加针，只知道注入增量；只有按机制重生成 Y 才能宣称完整真值。

主要风险与收口动作

风险收口
共同冲击与内部变更混淆核查两组暴露强度和口径；不满足则做暴露模型、DiD/BSTS/SCM，不能重复从 residual 机械扣除
PCMCI+ 短序列、强非线性功效不足前置数据盘点，PCMCI+/LPCMCI 双跑；不一致就保留歧义或拒答
L3 三轨结果矛盾当作混杂/机制错配信号进入审计队列，不多数投票强行统一
技能库虚胖或错误归因G5 发布验证 + G6 进化归因门；缩小适用域、降级 provisional 或一键回滚
Subagent 成本失控固定串行四层，成本台账超过约 4× 回退单层载入
当前状态要如实表达代码包已有统计线路、识别、行动接口及部分门禁和回归验证；四层 Subagent、完整技能闭环、HITL/C 线常驻化属于按方案继续落地的增强方向。评审时应把“已验证”“已具备胚胎”“设计目标”分开标注。
